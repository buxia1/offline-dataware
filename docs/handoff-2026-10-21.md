## 8. 红线与坑（必读，全部踩过）

1. **DS 工作流导入会自动改名** `<原名>_import_<时间戳>`，要用 SQL 改回；**定义上线 ≠ 定时上线**，要分别 `release_state=1`（定时用 `POST /schedules/{id}/online`）。
2. **删 Routine Load 无语法**（StarRocks 3.5 没有 DROP/DELETE）；STOP 不可恢复；`SHOW ALL ROUTINE LOAD FROM ods` 才能看到已停作业。
3. **DS 容器内无 python3 / 无 git**；容器以 root 运行、挂宿主 `docker.sock`（`docker exec ...` 可用），脚本默认把产物 `chown 1000:1000`。
4. **Spark 串行锁**：`/tmp/.spark_job.lock` 残留会拖住后续任务（A0 曾因残留等锁 326s 并超时告警）；清理：`docker exec spark rm -rf /tmp/.spark_job.lock`。
5. **FE image 备份/恢复**：`ALTER SYSTEM CREATE IMAGE` 是异步（0.2s 返回、最晚 72s 落盘），实体在 `starrocks/fe/meta/image/v2/image.<journalId>` + `checksum.<journalId>`（CRC32 十进制）；恢复**必须先把 `meta/bdb` 移走**，否则 journal replay 让回滚"没生效"；必要时 `fe.conf` 加 `start_with_incomplete_meta = true`。
6. **`docker exec` 导入 DS dump 必须带 `-i`**（漏了 rc=0 但导 0 表）；**绝不能用 `mysqldump --databases`**（会带 USE 覆盖生产库）。
7. **台账会因手动重放多写行** → 7 天验收永远按 dt 去重（见 §5）。
8. **新增湖表后 StarRocks 需要 `sr_catalog_reset.sh`**（DROP+CREATE EXTERNAL CATALOG），否则 FE 元数据缓存中毒（坑 31）。
9. **Spark 读 Iceberg 必须显式 catalog class**：`--conf spark.sql.catalog.X=org.apache.iceberg.spark.SparkCatalog` + `type=hadoop` + `warehouse=...`；只给 type 会 `plugin class not found`。
10. **`spark-sql -e` 非交互输出只有值无表头**；多段表名要 `--conf spark.sql.defaultCatalog=X`。
11. **Kafka 热备不一致**（tar 时文件在变 → exit 1），冷备要先停 Kafka；offset 用 `kafka-get-offsets.sh`（`--describe` 不含 offset）。
12. **A0 与 02:00 主链路共用 Spark**：`rt_refresh_5m` 用 `LOCK_WAIT_SECONDS=0`（忙则跳过），主链路用默认 1800s；两者靠锁互斥，不要改成并行。
13. **DS 3.2 的 `t_ds_process_instance` 没有 `duration` 列**（查耗时用 start_time/end_time）。
14. **Kafka 只保 30 天**（720h）→ 超窗补数必须靠备份/重新生成；mock 事件生成器有状态、跳天不补发。
15. **改 README/文档后提交前**：`git checkout -- starrocks/fe/conf/fe.conf`（FE 每次重启会追加重复 `priority_networks` 行）。
